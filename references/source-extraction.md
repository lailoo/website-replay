# 图表源码提取与可复用性

用户说“源代码摘出来”时，单纯给整个压缩 bundle 链接通常不足以满足请求。定位独立模块，格式化，标注依赖和可运行范围，按需要打包。

## 定位

1. 用 `rg -l` 搜索精确标题、轴标签或特有字段，缩小 JS 文件范围。
2. 优先使用存在且公开可取的 source map；检查其中实际 source 内容是否完整，不假设 `.map` 存在。
3. 没有 map 时使用 JS AST 解析 bundle 的模块注册表，提取包含标题的模块工厂与 `require(id)` 依赖。不要靠大括号字符串计数切片（模板字符串和注释会破坏边界）。
4. 必要时可在受限进程中记录 webpack chunk 注册，但 Node `vm` 不是安全沙箱。未知远程脚本优先静态解析；不能在具备文件、网络或凭据权限的上下文随意执行整个 bundle。
5. 格式化后验证语法和模块工厂形状。不要通过改名删除 React Compiler 缓存代码后声称仍是逐字提取。

## 交付级别

明确选择与标注下列之一：

- **原始工程源码**：真实 source map 或作者仓库中的 JSX/TS 源文件及必要依赖。
- **构建模块提取**：原站编译后的独立模块，保留编号、工厂签名和代码。说明依赖 webpack runtime，以及收集的是直接依赖还是完整依赖闭包。
- **可读还原稿**：人工根据构建逻辑还原，注明不是作者原始文件。必须单独保存原提取物作比对依据。
- **独立可运行组件**：拥有实际实现的依赖、样式、数据适配、入口、依赖版本与启动方式；需用新项目/干净上下文验证。不能靠未实现的 `ScatterPlot` import 或原站模块编号宣称独立可用。

推荐交付：主图表代码、必要依赖、模块索引（ID/源文件/输出文件/hash）、数据样例或授权范围内完整快照、说明和 ZIP。解释 raw 数据与组件 props 可能不同，记录转换路径。

完整可运行副本也可能很大，因为 React、图表库和站点工具是传递依赖。先满足用户指定级别，不主动承诺“小型独立源码”却打包整个网站。只读提取本身不需要改动现有页面。
