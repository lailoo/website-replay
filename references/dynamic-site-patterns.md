# 动态页面处理

本文件描述可用于授权范围内公开页面的通用处理方法，不代表任何具体网站的实现协议。字段、路由、模块编号和数据规模都应以当前页面的实际证据为准。

## 原始文档与运行时状态

- 保存服务器响应作为 `source.html`，将本地适配另存为 `index.html`。
- 列表页、详情页和比较页分别保留真实初始状态，不能只修改标题替代另一页面。
- Next Flight 可能含按字节长度编码的记录。不要全局替换脚本中的 URL；仅修改经过定位的资源属性和必要的运行时映射。
- 用结构化解析器读取已观察到的 JSON，不执行任意内联脚本。注意记录可能跨 chunk 分片。

## 数据字节与完整性

文本 MIME 不保证响应是文本。二进制、压缩或加密数据经过浏览器文本通道时可能损坏，页面仍可能显示服务器初始子集而没有明显报错。

1. 记录请求 URL、响应类型、内容哈希和字节数。
2. 在实际授权范围内，使用保持原始字节的捕获通道。
3. 如果客户端公开协议包含解压或解码步骤，核对当前版本的处理顺序和参数，不套用其他页面的算法。
4. 以成功解析、记录 ID 和关键字段与对应源快照一致为证据，不能只检查 SVG 存在或数组非空。
5. 重取资源时核对版本标识，避免混用旧文档与新数据。

## 图表状态

图表输入通常还包括候选集合、筛选、排序、坐标转换及持续高亮。详情页的固定高亮与鼠标 hover 不是同一种状态。对比时记录选中 ID、自动加入的候选项、轴单位和计算口径，不通过修改数据或固定坐标范围来凑截图。

query 可能分别控制多个图表区域。验证各区域的实际标签和内容，不只验证地址栏。模块编号和 bundle 哈希会随发布变化，应通过当前标题、字段和模块结构重新定位。

## 隐藏状态与 Apply 导航

sitemap 和普通链接不能覆盖所有状态。radio 或下拉选择可能在点击 Apply 后才生效，并导航到此前未出现的路径。

从基线页面记录“打开设置 → 选择 → Apply → 目标地址 → 内容变化”的完整动作链。将发现的路径追加到队列，按功能归为父页状态，但仍保留它自己的文档和数据。

Next.js 的预取与真实 RSC 导航必须区分。可以取消已经确认不需要的预取；真实导航不能统一返回 204 并视为成功。对已捕获目标可采用本地整页导航，并核对修饰键、新窗口、query 和锚点。

新增状态可能引用另一部署的样式、runtime 或路由模块，因此每批状态捕获后都应重新核对依赖。

## 异步接口与选择相关响应

历史图表可能在标签激活后才读取数据。检查真实请求方法、参数、正文和响应 schema；等待请求及业务结果完成，不能快速点击后只断言 `aria-selected`。

GET 回放键必须保留有效 query。对于任务范围内的公开只读 POST，响应可能取决于所选实体 ID、端点 ID 和工作负载。可从已捕获数据按请求组装结果，但必须验证返回 ID 属于本次选择。

已捕获的空结果与尚未捕获的选择分开处理。权限和历史时间范围限制原样保留。缺失 API 应显式返回错误，不能落到 200 HTML 的 SPA fallback，也不能返回任意固定 JSON。

检查多个 middleware 的处理顺序：旧单页快照可能抢先返回与当前选择无关的响应。修复后既做集成测试，也检查运行服务是否实际加载了新代码。

## 按清单验证

- 每个场景执行前核对基线 URL，防止上一轮导航、query、存储或滚动影响下一轮截图。
- 原站不提供某个标签或显示不支持提示时，记录并核对该行为，不创建虚构数据。
- 在禁止外部网络的新上下文检查直接打开、点击到达、刷新、数据和视觉结果。
- 媒体除了加载还要检查播放与 seek，核对 Range、206、416 和 HEAD。
- 把文档、资源、数据、交互与视觉检查分别关联到清单，不用文件数量替代功能覆盖。

详细清单见 [site-discovery-checklist.md](site-discovery-checklist.md)，故障排查与回归检查见 [difference-diagnosis.md](difference-diagnosis.md)。
