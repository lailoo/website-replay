# 整站探查、保存清单与逐项验收

用于多页或整站离线化。目标是留下可以继续执行、可以追溯证据的工作清单；不是给 URL 数量换一个名称。动态页面的处理方法见 [dynamic-site-patterns.md](dynamic-site-patterns.md)。

## 1. 先建立范围和初始清单

从现有工作区、抓取 manifest、用户指定 URL、粘贴 HTML、sitemap、主导航及页脚收集候选入口。用户粘贴内容是结构线索；在线版本仍需核对。沿用已有快照与路由，不重新覆盖已完成页。

先记录允许的域名、公开功能范围、语言策略、快照时间与本地 origin。本案例只保留英文，但这不是所有项目的默认要求。语言通常是同一功能页的变体；只在内容或功能确实不同且属于任务范围时单独说明。

第一批结果立即写入清单。后续每批探查、捕获、修复和验收完成都回写状态，展示新增页面、状态、发现的缺口和下一批待办。用户已经授权实施时，列计划后继续执行。

## 2. 用页面、状态和跳转描述网站

- 页面：稳定的功能实体，如模型总榜、某个模型详情、供应商比较。`pageId` 不随发现顺序改变。
- 状态：标签、筛选、搜索、分页、排序、展开项、对话框、语言、工作负载。保留原 query 和 hash。URL 相同但 DOM/数据不同，仍可能是不同状态。
- 跳转：入口状态、控件定位与名称、动作顺序、目标 URL/状态、实际结果。直接地址和通过点击到达是两项验证。
- 资源：该状态依赖的 HTML、CSS、JS、字体、图片、媒体、数据请求和下载文件，关联到拥有它们的状态。

功能页的 canonical 标识与抓取键分开。将 `/prompt-options/single/medium` 归到父页只影响分类统计，不能据此删除状态快照或假定父页数据能替代它。除非证明无关，不丢 query，不随意排序多值参数，不合并请求正文不同的 POST。

## 3. 探查顺序与真实操作

1. 先按页面模板分组，选择一个有代表性的实例了解布局和控件；将同组其他页面保留为未探查，不继承通过状态。
2. 在导航前开始记录响应、错误、URL 和必要的初始状态。打开准确 URL，等 hydration、字体、关键数据和目标控件就绪；滚动触发懒加载，并记录滚动容器。
3. 收集导航链接及可交互控件的 role、可访问名称、当前值、可用条件。分清读取/本地变化与提交/购买/投票等后台动作，只操作任务授权的部分。
4. 从已知基线开始真实点击一个控件或一段必要操作链。记录动作前后 URL、选中值、DOM、图表数据或请求差异。选择后可能还需 Apply；不能把 radio 变更或 click 成功当作功能完成。
5. 打开下拉项、标签、筛选、模型搜索、说明和导出入口；按功能检查排序/分页/重置、刷新、后退、前进、新窗口和下载。URL 不变时用选中状态与内容变化感知结果。
6. 记录新页面、新状态、懒加载模块和数据接口，回填队列。进入下一分支前恢复基线，避免前一轮 query、localStorage、滚动或对话框污染后续观察。
7. 对移动导航、响应式表格、横向标签、固定标题等不同操作入口补充移动端探查。源站与本地保存同视口、同状态证据。

有限选项按任务范围逐项枚举；搜索字符串、数值输入和组合状态可能无限。对后者使用语义等价类、边界值及关键组合，写明覆盖方法和未测组合。轮次不再发现新页面/状态/依赖只表示当前策略下队列收敛，不证明网站没有隐藏页面或后台功能。

## 4. 清单字段与可打开的呈现

以 JSON 等结构化文件作为唯一事实来源，由它生成便于查看的 Markdown/CSV 或任务面板。小任务一张表即可，大站按功能分组，并可筛选待保存、缺资源、待验收与阻塞项。不要手工维护互相矛盾的多份进度表。

| 记录 | 必须能回答的问题 |
| --- | --- |
| 身份 | `pageId`、`stateId`、所属功能、标题；是独立页还是状态？ |
| 来源 | `sourceUrl`、发现时间、发现方式（sitemap/链接/操作/已有快照）、父入口；实际观察还是推测待确认？ |
| 打开 | `localUrl`、入口页链接、role/name 定位与操作步骤、预期目标；是否需刷新、锚点或选择后 Apply？ |
| 保存计划 | `strategy`（离线快照/明确授权的重写/后台限制）、原因、依赖、优先级、下一动作；重写不能标成原站源码 |
| 产物 | 原始和准备后的 HTML、manifest、资源/数据文件、捕获时间、内容哈希或构建标识 |
| 验证 | 保存、资源、数据、直接打开、点击到达、状态恢复、交互、视觉分别为待做/通过/失败/受限/不适用，并记录理由 |
| 证据 | 测试时间、源/本地版本、浏览器条件、实际结果、截图/报告路径、错误请求与缺失资源 |
| 续跑 | 已完成阶段、待办、重试次数和最后错误、是否因产物变化需重验 |

清单示例只是格式，不代表以下状态已经通过：

```json
{
  "pageId": "models",
  "stateId": "models-single-medium-speed-history",
  "sourceUrl": "https://example.com/models/prompt-options/single/medium?speed=output-speed-over-time",
  "localUrl": "http://localhost:5174/models/prompt-options/single/medium?speed=output-speed-over-time",
  "discoveredBy": "browser-action",
  "entry": {
    "path": "/models",
    "steps": ["Toggle prompt options", "Single", "1k tokens", "Apply", "Output Speed Over Time"]
  },
  "strategy": "offline-snapshot",
  "checks": {
    "capture": "pending",
    "resources": "pending",
    "data": "pending",
    "directOpen": "pending",
    "navigation": "pending",
    "stateRestore": "pending",
    "interaction": "pending",
    "visual": "pending"
  },
  "evidence": [],
  "nextAction": "核对原站操作后的准确 URL 和数据请求，再保存该状态"
}
```

显示源站、本地与入口链接时保留准确 query/hash；没有稳定直达 URL 的弹窗或临时状态，给出基线链接和完整动作链，不伪造可直达链接。未保存页标为待保存，不能让链接静默跳到首页。原站 404、临时网络错误、权限限制和本地遗漏分别记录。

## 5. 按清单捕获与回放

按入口页、共享模板/资源、详情页、组合状态的依赖顺序推进；依据任务重点调整优先级。已知用户目标优先于单纯扩大页面数。

保存响应原始字节和完整请求身份。GET 包含 query；只读 POST 的数据还取决于 body。需要从原站模块查明请求、响应 schema 和权限字段，再设计本地回放。组合选择可从已捕获 ID 的数据组装，但不能给未捕获 ID 编造空结果或把旧选择的固定响应返回给所有请求。

每批新增状态后重新发现资源依赖，包括 CSS 引用、动态模块、媒体、字体及数据 API。后续页面可能来自原站的新部署，引用新的 runtime/CSS；不能仅复用第一批静态资源。对断点续跑进行 checkpoint；同一 manifest 的并发写入需要串行合并，避免覆盖已保存结果。

## 6. 逐项核销，不能只验文件数量

| 检查层 | 通过所需证据 |
| --- | --- |
| 文档 | 原始 HTML 可读取，哈希可核对，准备过程未破坏内嵌结构/Flight |
| 资源 | 该状态依赖闭合，文件存在、大小/哈希及 MIME 正确；图标缺失仍属未完成 |
| 数据 | 响应可按真实 schema 解析，关键 ID/值对应源快照；返回 ID 属于请求选择，权限字段保留 |
| 打开与跳转 | 本地准确地址直接打开，入口点击到达准确页面/状态，刷新/历史导航能恢复；dev 和 preview 均可用 |
| 交互 | 新上下文屏蔽非本地网络后执行记录的动作链，等待异步数据，断言内容和结果，不止按钮选中 |
| 视觉 | 原站/本地版本及状态对齐，桌面/移动截图对比；记录差异区域、原因和修复/接受结果 |

详细断网与截图方法见 [verification.md](verification.md)。保存验证报告到清单项上；文件完整性通过不替代请求正确，HTTP 200 不替代正确 MIME/数据，合法 JSON 不替代模型选择正确，截图无差异不替代交互可用。

修复后重验受影响项。共享 middleware、runtime 或资源优先级变化时，重验依赖它的关键流程；确认运行进程已加载修改。旧截图和旧检查需要绑定旧产物，不能继续作为新版本通过证据。

## 7. 完成判定与交付

分别汇报独立页、状态、捕获文档、已验收状态、未测交互、资源缺口、源站不可用项和后台范围限制。抽样验证标明模板、实例和动作，不给同组其他实例自动打勾。

只有约定范围内的必需检查全部有有效通过证据，才能称该范围保存完整。受限项有说明也不等于已复制后台；未知/待测项非零时，不能称全站一比一完全验证。

交付可打开的清单与证据链接，明确下一批待办和续跑入口。若本轮任务仅要求沉淀方法到 skill，则更新规范和实际案例即可，不启动额外的整站抓取任务。
